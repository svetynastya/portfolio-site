Этапы работы:

1. Исследование внутреннего устройства сервиса

2. Провела desk-исследовние, сделала выводы и гипотезы

Главная задача:

Переработать и разработать такой дизайн интерфейса, который бы

помогал начать быстрее работу пользователю и перейти к активному действию.

Поменять подход к использованию самого экрана.

Я исследовала структуру существующего интерфейса RackTables, выявила основные UX и UI-проблемы и переработала информационную архитектуру, навигацию и ключевые пользовательские сценарии, чтобы ускорить работу специалистов.

Новый интерфейс RackTables

RackTables

это веб инструмент со всей компьютерной инфраструктурой компании.

Интерфейс RackTables, старый вариант

Общая информация о RackTables

Перед началом работы я сначала собрала всю главную информацию об инструменте,

чтобы понять для чего он, для кого и из чего состоит

Основные пользователи:

системные администраторы, DevOps-инженеры, сетевые инженеры

и специалисты, отвечающие за IT-инфраструктуру.

Задачи пользователей:

• найти конкретный сервер или оборудование;

• определить физическое расположение устройства;

• проверить IP-адрес;

• понять, к чему подключено устройство;

• найти свободный IP-адрес;

• посмотреть содержимое серверного шкафа;

• добавить или изменить информацию об оборудовании;

• проверить историю изменений;

• найти связанную документацию.

Главная задача интерфейса:

быстро предоставить специалисту нужную информацию о сложной IT-инфраструктуре.

Что содержит внутри себя каждый раздел:

Разделим их на основные категории:

Так как у нас нет задачи спроектировать весь сервис, а только переработать главный экран, то я решила начать

с desk-исследования, чтобы понять, какие похожие сервисы есть на рынке, что они предлагают пользователям, и какие решения уже существуют.

Desk-исследование

Для исследования я взяла основные интерфейсы инструментов NetBox и Device 42.

Основная структура экранов:

• Оба сервиса сразу делится основной информацией, статистикой, dashboards и т.п. на главном экране

• В отдельную навигацию наверх или слева помещают разделы, по которым можно перейти

для поиска более подробной информации, серверов, соединений и т.п.

• NetBox отличается тем, что сразу предоставляет журнал изменений на Home page

Интерфейс главного экрана NetBox

Отличия в использовании UI и UX-дизайна:

NetBox

• NetBox не строит навигацию вокруг больших иллюстраций, как RackTables.

Используются:

• текстовые названия;

• небольшие UI-иконки;

• визуальные элементы внутри интерфейса;

• цветовые состояния.

Для технического продукта текст является основным носителем смысла, а иконка выполняет вспомогательную функцию. Также есть расширенные фильтры и сохранение часто используемых фильтров.

• Иерархия

1. Global navigation → левая колонка

2. Dashboard widgets → крупные смысловые блоки

3. Entity → Sites / Devices / IP Addresses

4. Count → количество объектов

То есть пользователь может быстро просканировать:

IPAM → IP Addresses → 180

• Dashboard можно перестраивать: пользователь может менять размер, положение и набор виджетов.

• Search в NetBox

Поиск находится в верхней части приложения.

Минусы:

• Высокий порог входа

Главный экран нагружен терминами (что неизбежно):

• Dashboard может быть перегружен

Для нового пользователя проблема: «А на что вообще смотреть?»

Device42

• Более сильный акцент на визуальном минимализме.

Плюс акцент идёт сразу на данных, которые показываются на первом экране, а самая нужная информация, с помощью визуализации, даёт представление пользователю о том, что у нас есть сейчас.

Navigation → Dashboard → Data

• Визуализация физического пространства

Можно визуально видеть расположение rack'ов, взаимодействовать с ними. Это снижает когнитивную нагрузку.

• Поиск находится на видном месте на главной странице.

• Визуализация данных

Пользователи не тонут в большой количестве букв, информации, графики, диаграммы облегчают визуально восприятие.

• Слишком много сложных термнов

Device42 — очень широкий продукт: Discovery, DCIM, IPAM, ITAM, Applications и т.п.

Поэтому главная навигация неизбежно сложная.

• Search теперь скрыт

В v15 функция поиска превратилась в иконку, которая находится в верхней части интерфейса и раскрывается по клику.

+ меньше визуального шума.

− пользователь не сразу видит, что глобальный поиск существует.

Интерфейс главного экрана Device42

UX/UI проблемы интерфейса RackTables

Исходя из исследований о вышеперечисленных сервисах есть несколько моментов, которые можно улучшить:

📍  Иллюстрации не помогают понять функцию.

Убираем лишние элементы, которые не дают никакой информации и применяем иконки

только там, где упрощают её восприятие или помогают очистить пространство.

📍  Поиск находится в правом верхнем углу и не виден для пользователя.

Такую важную функцию стоит выдвинуть вперёд и выделить с помощью визуальной иерархии,

возможно поставить в центр, выделить определённым шрифтом/выделением/иконкой и т.п.

📍  Слабая визуальная иерархия.

Все категории выглядят практически одинаковым образом.

Можно использовать группировку, размеры, отступы, карточки и т.п.

📍  Основная идея редизайна:

Перейти от навигации по техническим сущностям к навигации через задачи пользователя.

Что я ещё взяла бы у конкурентов?

💬  Не терять результаты поиска при открытии объекта. Создавать в отдельной вкладке (?).

💬  Сохранять прошлые запросы в поиске и возможность их удалять.

💬  Advanced Search с подсказками , не заставлять пользователя помнить синтаксис.

💬 Визуальная модель Rack / Room. Показывать физическую инфраструктуру.
